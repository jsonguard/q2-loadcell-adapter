# Q2 LoadCell Adapter

Расширение для Klipper, которое даёт доступ к тензодатчику минуя ограничения вендорной библиотеки.

Возможности:

- прямое чтение сэмплов с THR;
- частота сбора данных 200–300 Гц (зависит от загрузки Klipper и THR) против 40 Гц.

Это позволяет получить достаточную плотность данных для корректной работы алгоритмов автоматической калибровки Pressure Advance.

## Как это работает

В вендорной библиотеке чтение с регистра реализовано через команду, которая накапливает несколько сэмплов и затем отдаёт усреднённое значение. Этого достаточно для определения стола под соплом, но мало для устойчивой работы алгоритмов автокалибровки.

Расширение использует команды THR для изменения частоты опроса тензодатчика и прямого чтения регистра.

Алгоритм работы:

1. Переводим частоту опроса на 640 Гц.
2. 250 раз в секунду отправляем команду на чтение регистра с данными и записываем результат.
3. По окончании периода сбора сглаживаем выбросы по методу Хампеля (вместо замены на медиану вычисляем новое значение через линейную интерполяцию).
4. Возвращаем набор данных в autopa.

## Установка

Требования:

- QIDI Q2 со стоковой прошивкой `v1.1.2.4`;
- установленный autopa — [инструкция по установке](https://github.com/G0BL1N/autopa#installation);
- доступ к принтеру по SSH;
- доступ к `printer.cfg` через веб-интерфейс или SSH.

1. **Подключитесь к принтеру по SSH**

2. **Скачать архив**

   Скачайте архив во временный каталог:

   ```bash
   wget -O /tmp/q2_loadcell-cp39-aarch64-linux-gnu.tar.gz \
     https://github.com/jsonguard/q2-loadcell-adapter/releases/latest/download/q2_loadcell-cp39-aarch64-linux-gnu.tar.gz
   ```

3. **Распаковать архив**

   ```bash
   tar -xzf /tmp/q2_loadcell-cp39-aarch64-linux-gnu.tar.gz -C ~/klipper/klippy/extras/
   rm -rf ~/klipper/klippy/extras/__pycache__/
   ```

4. **Запатчить autopa**

   В autopa нужно заменить поиск штатного объекта `load_cell` на `q2_loadcell`, иначе autopa не найдёт адаптер. Выполните на принтере:

   ```bash
   sed -i "s/self.printer.lookup_object('load_cell', None)/self.printer.lookup_object('q2_loadcell', None)/" ~/autopa/autopa/__init__.py
   ```

5. **Настройте printer.cfg**

   Откройте `printer.cfg` в веб-интерфейсе и добавьте:

   ```ini
   [q2_loadcell]

   [autopa]
   save_captures: False
   ```

   Если секция `[autopa]` уже есть, не создавайте её второй раз.

   Все параметры `[q2_loadcell]` необязательны: пустая секция означает настройки по умолчанию.

6. **Перезагрузите принтер**

   После установки или обновления **обязательно перезагрузите принтер**: выключите его питанием и включите снова.

   Обычного перезапуска Klipper недостаточно. Klipper не подхватывает замену Python-модулей без перезагрузки хоста.

## Использование

### Измерение нуля датчика (tare)

Перед калибровкой выполните:

```gcode
Q_LOADCELL_PROBE
```

Команда измеряет шум датчика, запоминает нулевое смещение (tare). Без этого шага колонка tare в отсчётах будет равна `0`.

Ожидаются:

- частота около `80–85 Гц`;
- `errors: 0`;
- осмысленные значения `median tare` и `noise sigma`.

### Калибровка Pressure Advance

Перед запуском:

1. Выполните хоуминг: `G28`.
2. Опустите стол на 80–100 мм.
3. Заправьте филамент.
4. Нагрейте хотенд и подождите 3–5 минут.
5. Измерьте tare командой `Q_LOADCELL_PROBE`.

Первый проход пристрелочный, определяем примерный коэффициент:

```gcode
AUTOPA_SWEEP APPLY=0
```

Пример более точного прохода для PETG:

```gcode
AUTOPA_SWEEP APPLY=0 VFR=18 VFR_LOW=2 TSLOW=1 TFAST=0.35 CYCLES=8 KSTART=0.045 KEND=0.065 KSTEP=0.0025
```

Что означают параметры:

- `VFR` и `VFR_LOW` — объёмный поток быстрой и медленной фаз, мм³/с;
- `TSLOW` и `TFAST` — длительности фаз, секунды;
- `KSTART`, `KEND` и `KSTEP` — диапазон и шаг коэффициента `K`.

Рекомендации:

- значения калибровки сразу после включения холодного принтера не соответствуют действительности.
- голова принтера должна достаточно прогреться, лучше 3–5 минут после нагрева сопла до целевой температуры, чтобы показания калибровки были воспроизводимы и похожи на реальные.
- полученное значение PA сохраните в профиль материала в слайсере.

## Конфигурация для printer.cfg

Все параметры `[q2_loadcell]` необязательны. Если параметр не указан, используется значение по умолчанию.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `sweep_rate` | `44` | код частоты обновления АЦП на время калибровочного прохода: 28 = 40 Гц, 44 = 640 Гц, 60 = 1280 Гц |
| `restore_rate` | `28` | код частоты обновления АЦП после прохода |
| `median_width` | `5` | ширина окна фильтра Хампеля; `1` отключает фильтрацию |
| `spike_sigma` | `6.0` | порог обнаружения выбросов в единицах робастной оценки СКО |
| `fallback_sample_hz` | `250` | резервная частота таймера, если измеренная частота неизвестна, Гц |
| `min_sample_hz` | `100` | нижняя граница частоты выборки, Гц |

Пример с явно заданными параметрами:

```ini
[q2_loadcell]
sweep_rate: 44
restore_rate: 28
median_width: 5
spike_sigma: 6.0
fallback_sample_hz: 250
min_sample_hz: 100
```

## Если что-то не работает

В консоли принтера выполните:

```gcode
Q_LOADCELL_DEBUG
```

Команда только читает датчик, ничего не двигает и не нагревает. Полная диагностика занимает около 10–12 секунд.

На прогретом и стабильном принтере ориентиры такие:

- прямое чтение — примерно `200–300 Гц`;
- повреждённые кадры (`bad frames`) — менее `5 %`;
- после фильтрации (`outliers replaced`) — около `0.5–1 %`;
- `after despiking` — порядка `60 counts`.

Если `standard deviation` или `after despiking` показывают тысячи `counts`, датчик ещё «плывёт» из-за температуры. Дайте принтеру прогреться и стабилизироваться, калибровку в таком состоянии не начинайте.

По проблемам заводите ишьюсы в проекте, туда прикладывайте вывод `Q_LOADCELL_DEBUG`.

## Для разработчиков

### Структура проекта

```text
src/q2_loadcell/
  __init__.py        load_config, DI, Q2LoadCell
  api/               контракт autopa и g-code команды
  core/              логика: фильтрация, tare, диагностика, коллектор
  hardware/          доступ к CS1237: константы, декодирование, discovery, чтение
tests/               pytest; структура повторяет src/q2_loadcell
vendor/stubs/        заглушки Klipper, сгенерированные с принтера
docker/              конфигурация для сборки в контейнере с эмуляцией arm64
Makefile             команды, чтобы всякое поделать
```

Зависимости направлены от `api`/`__init__` к `core` и `hardware`. `core` не импортирует `hardware` и Klipper в рантайме.

### Команды разработки

```bash
make setup      # создать окружение uv
make test       # запустить pytest
make lint       # ruff check --fix и mypy
make fmt        # ruff format
make build      # собрать архив в dist/
make stub-gen   # перегенерировать vendor/stubs с принтера
make stub-clean # удалить vendor/klipper-src и vendor/stubs
```

`make build` собирает архив:

```text
dist/q2_loadcell-cp39-aarch64-linux-gnu.tar.gz
```

Для сборки нужны Docker, buildx и эмуляция `arm64`.

### Перегенерация заглушек Klipper

`make stub-gen` подключается по SSH к принтеру, скачивает `~/klipper/klippy` в `vendor/klipper-src` и генерирует заглушки в `vendor/stubs`.

- по умолчанию используется `SSH=qidi` и `KLIPPER_DIR=~/klipper`; их можно переопределить в начале `Makefile`;
- принтер должен быть доступен по SSH;
- заглушки нужно закоммитить в репозиторий;
- перегенерируйте их при смене прошивки принтера.

`vendor/klipper-src` в репозиторий не коммитится. Для очистки используйте `make stub-clean`.
